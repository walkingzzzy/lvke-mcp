# 风险覆盖度（Risk Completeness）审查

可研报告的"风险章节"最常见两个失败模式：(1) 列了 20 条琐碎风险但漏了致命的；(2) 只罗列风险但无对策。本 skill 保证关键风险全部覆盖、每项风险有可执行的应对。

## 何时使用

- 用户说："风险覆盖全吗"、"漏哪些风险"、"风险章节够不够"
- 在 `report-drafting-chapter-7-risk` 完成后做配对审查
- 在 `doc-review-decision-support` 发现"风险与建议不匹配"时深入

## 7 大风险维度（系统性框架）

任何项目都应至少检查这 7 个维度。**少一个就是系统性遗漏**。

### 1️⃣ 政策 / 合规风险

可能形式：
- 项目类型受限（如"两高一资"项目限制）
- 审批环节卡点（环评 / 用地 / 节能 / 稳评）
- 行业政策变化（补贴退坡、准入门槛上调）
- 地方政策与国家政策不一致

判断"是否覆盖"：
- 报告引用了最新的相关法规？
- 提及审批不确定性？
- 提及政策"窗口期"风险？

### 2️⃣ 市场 / 需求风险

可能形式：
- 需求测算偏乐观（基于历史趋势 + 未考虑替代品）
- 客户集中度高
- 价格 / 利润空间挤压
- 进入门槛低导致后来者竞争

判断"是否覆盖"：
- 测算敏感性涵盖需求下行 -20% / -30%？
- 有讨论替代品 / 替代技术？
- 有竞争格局分析？

### 3️⃣ 技术 / 实施风险

可能形式：
- 选用工艺成熟度（首次应用 / 中试 / 商业化）
- 关键设备 / 工艺受制于人（含进口、含许可证）
- 实施团队经验
- 集成与调试复杂度

判断"是否覆盖"：
- 工艺路线是否说明"已商用 / 中试 / 实验"？
- 关键设备来源是否说明备选方案？
- 实施单位资质是否说明？

### 4️⃣ 财务 / 资金风险

可能形式：
- 投资估算偏低 / 偏高
- 融资到位风险（银行授信延迟）
- 利率变动 / 汇率变动（如有外币）
- 现金流缺口（运营初期常见）
- 收入预期过激进

判断"是否覆盖"：
- 敏感性分析包含投资 ±10/20%？
- 包含运营收入下行情景？
- 建设期现金流 + 还款计划匹配？

### 5️⃣ 进度 / 工期风险

可能形式：
- 审批延期（最常见）
- 用地交付延期
- 关键设备到货延期
- 季节性施工窗口
- 关联工程进度（如配套基础设施）

判断"是否覆盖"：
- 工期表是否标识关键路径？
- 是否预留 buffer（一般 10-15%）？
- 是否讨论审批延期对财务的影响？

### 6️⃣ 运营 / 管理风险

可能形式：
- 关键人才短缺
- 运营负荷爬坡慢（建成后实际产能利用率低）
- 维护 / 备品备件供应
- 安全生产
- 环境 / 排放超标

判断"是否覆盖"：
- 是否讨论"达产期"（达到设计负荷的时间）？
- 是否提及关键岗位人员储备？
- 是否提及 HSE 体系？

### 7️⃣ 社会 / 环境 / 邻避风险

可能形式：
- 邻避（NIMBY）效应（化工 / 垃圾 / 殡仪）
- 拆迁 / 征地纠纷
- 环境敏感目标周边（学校 / 医院 / 居民区）
- 文物 / 文化遗产
- 社会稳定风险评估（稳评）

判断"是否覆盖"：
- 是否做过环境影响评估初判？
- 选址周边敏感目标半径分析？
- 是否说明稳评结果？

## 风险章节质量 8 项 checklist

| # | 项 | 通过标准 |
|---|---|---|
| 1 | 维度齐 | 7 大维度至少各列 1 条；不齐写 high issue |
| 2 | 不琐碎 | 总风险 ≤ 15 条；> 15 条考虑合并 |
| 3 | 定性 + 定量 | 每条风险有"发生概率"+"影响"两维（哪怕定性 H/M/L） |
| 4 | 对策具体 | 每条对策不超过"加强管理 / 提高重视"层面 |
| 5 | 残留风险 | 应对后剩余风险水平有明确判断 |
| 6 | 责任主体 | 每条对策有责任部门 / 角色 |
| 7 | 联动财务 | 主要风险已进入敏感性分析 |
| 8 | 摘要呼应 | 第 1 章摘要提及 3-5 个最关键风险 |

## 审查 SOP

### 步骤 1：抓风险章节

```
doc_read range="7"  # 第 7 章风险分析与对策
context_view  # 拿全文摘要做联动核对
```

### 步骤 2：维度核对

逐条对照 7 大维度，标记 ✓ 已覆盖 / ❌ 缺失。

### 步骤 3：质量核对

按 8 项 checklist 逐项核。

### 步骤 4：写 issues

```json
{
  "anchor": "7 风险分析与对策",
  "comment": "缺失「邻避 / 社会稳定」维度风险讨论。本项目为化工类，位于江夏区某居民区 800m 内，应做稳评分析或至少说明已做稳评的结论。建议补充第 7.5 节「社会稳定风险」。",
  "severity": "high",
  "category": "风险覆盖度"
}
```

## 严重度判定

| 等级 | 标准 |
|---|---|
| **high** | 7 大维度漏 ≥ 1 个；或对致命风险（如审批 / 邻避）无应对 |
| **medium** | 维度都覆盖了但应对不具体（停留在"加强管理"）；或与敏感性分析脱节 |
| **low** | 风险条数过多需合并 / 摘要中未提及关键风险 |
| **info** | 表达 / 格式 |

## 边界

- **不替项目"创造"风险**：如果对项目背景不熟，写 `[请项目方确认是否存在 XX 风险]` 而非凭空假设
- **不替决策定残留水平**：写 issue 让用户决定，agent 只指出"未判定"

## 配套工具

- `doc_read range="7"`：取风险章节
- `context_view`：拿摘要 + 财务 + 章节联动
- `doc_review` + issues：写入
- `doc_propose`：如重要遗漏，可提议补段

## 与其他 skill 协同

- 配合 `doc-review-decision-support`：摘要风险显示性核对
- 配合 `financial-modeling-sensitivity`：敏感性分析与风险章节联动
- 配合 `policy-compliance-*`：合规类风险的实质审查
- 配合 `report-drafting-chapter-7-risk`：写作 ↔ 审查相互校准
