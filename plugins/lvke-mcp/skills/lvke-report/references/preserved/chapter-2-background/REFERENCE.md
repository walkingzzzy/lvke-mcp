# 第 2 章 · 项目背景与建设必要性 起草

第 2 章是**必要性论证主战场**。评审专家会用这章判断「项目存在的理由是否站得住」。如果论证停留在「响应国家战略 / 顺应行业趋势」的口号层面，本章不及格。

## 必含 4 节

### 2.1 项目提出的背景

要素：
- 项目缘起：是谁、什么时候、基于什么提出
- 行业大背景：行业近 3-5 年发展态势 + 数据
- 区域大背景：选址区域的战略定位 + 关键政策

### 2.2 国家 / 行业 / 地方政策依据

**3 层金字塔**：

```
顶层：国家级（"十四五"规划、"双碳"目标、产业发展规划）
   ↓
中层：行业级（行业"十四五"专项规划、行业准入条件）
   ↓
基层：地方级（湖北省 / 武汉市 / 园区专项政策）
```

每条政策需注明：
- 文号 + 颁布机关 + 颁布年份
- 引用的具体条款 / 段落
- 与本项目的对应关系（不是堆名字，要说明"这条政策为何支持本项目"）

### 2.3 项目建设的必要性

**4 维度论证**（写多了堆砌，建议挑 2-3 个最强的写深）：

1. **产业必要性**
   - 行业缺口 / 短板（量化）
   - 本项目能填补的具体环节
   - 不上本项目的后果

2. **市场必要性**
   - 市场需求测算
   - 现有供给能力不足
   - 本项目市场份额与定位

3. **区域 / 战略必要性**
   - 与区域发展规划契合
   - 带动就业 / 税收
   - 强链补链作用

4. **企业 / 投资者必要性**
   - 企业自身战略需要
   - 已有业务协同
   - 利用现有资源

### 2.4 项目建设的可行性（概述）

简述 4 个角度（详见后续各章）：

- 政策可行（已对照上层政策、初判通过）
- 技术可行（工艺成熟度、参考案例）
- 资金可行（资金来源安排）
- 资源可行（用地、用水、用电、人才有保障）

⚠️ 不能写得太满 —— 这只是"概述"，留给 4/5 章正式论证。

## 起草逻辑链

**好的"必要性"写作**：

```
现状：行业 / 区域有 X 问题（量化）
   ↓
原因：因为 Y / Z 因素
   ↓
后果：如不解决会导致 ABC
   ↓
方案：本项目通过 XX 路径解决
   ↓
能力：本项目能解决多少（量化预期）
```

**坏的"必要性"写作**：

```
段 1：政策很重要（堆 3 条政策）
段 2：本项目响应政策（一句话）
段 3：因此项目必要（结论先于论证）
```

## 政策引用 5 项 checklist

| # | 项 | 通过标准 |
|---|---|---|
| 1 | 文号格式 | `国发〔YYYY〕X 号` 或 `XX 部 X〔YYYY〕XXXX 号` 完整 |
| 2 | 时效 | 现行有效，不引废止文件 |
| 3 | 相关性 | 真适用于本项目类型 / 地区 |
| 4 | 条款定位 | 引用具体条款而非"该文件" |
| 5 | 不堆砌 | 每条政策至少 1 句话说明与本项目关联 |

## 常见缺陷

1. **政策堆砌** —— 列 10 条政策但只有 1 条真正支撑论证
2. **必要性 = 重要性** —— 写"项目很重要"代替"为何必须做"
3. **市场需求虚高** —— "市场前景广阔"无量化
4. **缺逆否论证** —— 没说"不上本项目会怎样"
5. **可行性预说太满** —— 第 2.4 节抢了 4-6 章风头
6. **缺企业自身视角** —— 只写宏观必要性不写企业为何要做

## 起草工作流

```
1. report_list_sections 看是否已有上下文
2. [调研]：mcp_policy_search / web_search 拉政策清单
3. [调研]：mcp_statistics_cn 拉相关数据
4. 拉 3 层政策金字塔（国 / 行 / 地）
5. 选最强 2-3 个必要性维度写深
6. 写 2.4 可行性概述（克制，不抢风头）
7. report_propose_section → diff → apply
```

## 关键避免

- 不要把"中国制造 2025" / "双碳目标"用得太泛
- 不要混淆"必要性"与"可行性"（章节边界）
- 不要在 2 章下结论"项目必然成功" —— 留给 9 章
