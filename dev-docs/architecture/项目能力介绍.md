# 绿科 MCP 项目能力介绍

> **文档类型：** 功能说明（面向非技术人员）
> **修订日期：** 2026-09-03
> **阅读对象：** 业务人员、决策者、项目参与方
>
> 本文描述的是系统当前**实际实现**的能力，每一项都对应系统里真实存在、真实运行的功能；
> 不包含计划中但尚未落地的东西。

---

## 1. 这个系统是什么

绿科是一套**可研工作的自动化流水线**。它把一份可行性研究从"立项、找资料、做测算、写报告、审报告、定稿"的全过程，变成一套可以反复使用、每一步都留痕、每个数字都能追溯的流程。

核心价值可以用三句话讲清楚：

1. **算得准**——所有财务计算由系统用确定的算法完成，不靠"感觉"或"经验值"猜。
2. **查得清**——每个数字、每句话都能追溯到它的原始来源（哪份资料、哪一页、哪个单元格）。
3. **把得住**——报告定稿前要过七道质量审查，标准不满足就不放行，宁可不交付也不交付错的。

系统的使用者是业务人员 + AI 助手：业务人员描述需求和确认关键参数，AI 助手按既定流程调用系统能力完成测算、制表、起草、审查，人工做最终判断和签字。

## 2. 核心能力

### 2.1 深度联网搜索与资料收集

系统可以在公网上为项目收集资料，覆盖政策、市场、行业、技术、风险、可比项目等维度。

**能做什么：**

- 用专业搜索引擎（Tavily）查询公开信息，自动把一次查询扩展成"政策 / 市场 / 技术"等多个角度的多轮检索，聚合成一组去重后的候选资料。
- 对每个候选网址做**安全审计**再决定是否抓取：能识别并拦截指向内网地址、云厂商内部接口、容易泄露密钥的链接；抓取过程对转发跳转逐跳校验，防止钓鱼或隐蔽跳转。
- 抓取到的网页**固化成不可变快照**（原文存档，带抓取时间），之后任何引用都以这份快照为准，原始网页即使后来改了内容或删了，引用依然可查。
- 被抓取的资料会自动做摘要、关键词检索和数值抽取，但**搜索摘要永远不冒充正式证据**——只有抓取到的原始页面才算数。

**质量控制：** 系统会记录本轮研究用了多少可用来源、引用覆盖率多少、检索了几轮，这些指标由系统自己核账，AI 助手不能虚报。

### 2.2 深度研究（DR）

在资料收集之上，系统支持一次"有计划、可恢复、可审计"的深度研究。

**能做什么：**

- **研究计划**：先确定研究目标、拆成若干子问题、分配预算和预期产出，形成一份研究计划。
- **混合来源**：研究结论可以同时基于网页快照、甲方提供的项目文件、已固化的证据包、历史档案等多种来源，每一条都登记来源类型和允许用途。
- **可中断续跑**：研究过程中随时可以保存检查点（checkpoint），之后从检查点继续，不用从头再来；中途取消或出问题也能恢复。
- **引用审计**：报告里每一句引用都**绑定到具体位置**并校验真实性——PDF 第几页、Excel 哪个单元格、Word 哪一段、网页哪一段文本。系统会重新计算引用片段的内容哈希，位置对不上、内容被篡改、跨了工作区的引用一律拒绝采用。
- **独立质检**：AI 助手写的研究报告永远标记为"待独立审查"，必须经过单独的质量确认环节才被采信；助手不能给自己写的研究盖"合格"章。

### 2.3 财务模型与测算

这是系统的核心引擎。输入是经过确认的项目参数（投资额、规模、收入驱动、成本项、税率、融资结构、建设期、运营期等），输出是完整的财务测算结果和交付报表。

**能做什么：**

- **确定性计算**：内部收益率（IRR）、净现值（NPV）、敏感性分析等指标全部由系统用确定性算法计算（IRR 用自研的牛顿法+二分法求根），**不依赖任何 AI 猜数**。同一组输入永远得到同一组结果，别人可以复核。
- **月度 / 年度两种时间轴**：
  - **月度模型**：支持按月逐月测算，用于经营驱动细的场景（如酒店——房价 ADR、入住率、辅营收入、工资、水电、消耗品、维修、业主运营成本等都可以按月给定）。
  - **年度模型**：按年测算，用于如光伏电站这种长期运营场景（逐年发电衰减、限电率）。
- **完整的报表体系**：自动生成全套交付财务表（利润表、现金流量表、资金来源与运用、资产负债表、投资、折旧摊销、债务还本付息、建设期利息、成本、工资、运营资本、利润分配、财务计划等 14 张表），可导出 Excel 和 CSV。
- **勾稽自动校验**：报表之间有 16 条勾稽关系，系统逐条核对——利润表、现金流量表、资产负债表之间的数字是否对得上，对不上就标记为不一致，而不是硬凑。
- **复杂的财税处理**：支持双倍余额递减法折旧；税务折旧与会计折旧的差异会体现在利润表和资产负债表里（递延所得税资产/负债）。增值税、附加税、所得税按给定税率计算——所得税率未给时默认 25%（标准企业所得税率），增值税和附加税未给时不做计算。
- **蒙特卡洛模拟**：给关键变量（收入、成本、投资）设定概率分布，系统跑上千次抽样，输出 IRR / NPV 的概率分布和风险水平（如 P5、P50、P95）。
- **甲方表格复核**：可以导入甲方提供的 Excel 测算底稿，系统用自研模型**独立重算**，与甲方表格双轨对照，自动发现本金重复计算、手工填的 IRR、僵尸公式等问题，并输出复核报告。**注意：甲方原值永远不作为对外正式数字源**，只作对照参考。

### 2.4 报告生成

研究报告由 AI 起草、人工审定、系统把关结构、数字和引用。

**能做什么：**

- 从项目上下文和财务结果出发，生成报告大纲并起草各章正文。
- **三步修改流程**：修改报告正文必须走"提案 → 查看差异 → 应用"三步，不能直接覆盖。每轮修改都留档，谁在什么时候改了什么，可回查。
- **结构校验**：系统检查章节是否齐全、有没有占位符、有没有重复段落。
- **数字一致性校验**：报告正文里引用的财务数字（如投资额、IRR、回收期）必须与财务测算结果一致，正文里写的数字对不上测算结果，会被标记出来。
- **导出 Word**：可导出草稿版和正式候选版 Word 文档。正式候选版必须通过工程校验才能导出。

### 2.5 研报审查与标准符合性

报告和全套交付材料（报告正文、原始依据、基础数据、财务模型、财务表格）定稿前，要过一次**七维度审查**。这是系统把质量关的核心。

**七个维度：**

1. **合规性**——对照适用的国家/行业标准逐条核对需要提交的证据材料。
2. **报告质量**——结构、表述、逻辑是否有问题。
3. **数据质量**——数据之间是否自洽、有无异常。
4. **来源质量**——引用的来源是否真实、可追溯。
5. **财务模型**——测算逻辑、假设是否成立，关键指标能否重算。
6. **财务表格**——表格之间的勾稽关系是否一致。
7. **可研逻辑**——结论是否能由前面的分析推出来。

**能做什么：**

- **确定性子检查**：系统用代码自动重算关键财务数据（折旧、税金、债务滚动、勾稽关系、敏感性），不是凭审查员感觉。比如审查方重算的 EBIT 曾发现漏算摊销，就是这类检查抓出来的。
- **独立评估**：在确定性检查之外，由独立审查角色对每个维度做语义评估，问题分级为 P0（致命）/ P1（严重）/ P2 / P3（轻微）。P0 永远不可豁免。
- **证据绑定**：每个审查意见都可以绑定到具体的证据位置（哪份资料、哪一页、哪个单元格、哪段原文），并能重验来源、位置和内容哈希。
- **整改复测（两阶段）**：问题整改后重新送审。子项复测通过、确认、最终定稿之前，父问题一直保持"挂起"，不允许靠一段说明文字就糊弄过去。
- **豁免机制**：部分问题可以申请豁免（记录范围、影响、补偿措施、责任人、到期日等），但 P0 除外。
- **审查导出**：可导出完整审查报告（含问题清单 Excel、七维度矩阵、审计档案、标注过具体问题位置的文档版本）。

**标准符合性（只出适用性，不出结论）：** 系统内置了国标和行业标准库，包括发改委 2023 版可研编制大纲（入库 118 条条款，带官方 PDF 页码和内容指纹）、22 个标准方法包、以及面向财务/税务/酒店的专项规则包。它能回答"这个项目应该对照哪些标准条款、需要哪些证明材料"，也能检查证明材料齐不齐——但**永远不下"项目符合/不符合国标"的结论**。符合性判断属于专业审查职责，系统明确不做，避免把"工具检查通过"误写成"合规批准"。

### 2.6 资产收购专项评估

适用于收购现有资产（酒店、光伏电站等）的场景，与新建项目测算逻辑不同。

**能做什么：**

- **酒店收购**：按**月度**模型测算——房价（ADR）、入住率、辅营收入、工资、水电、消耗品、维修、业主运营成本等经营驱动按月给出，再算整个收购的回报。
- **光伏收购**：按**年度**模型测算——发电逐年衰减、限电率、电价、运维成本。
- **多情景分析**：对收购价、融资比例、利率、期限、入住率、电价等多个维度取不同值，自动组合出最多 64 种情景逐一测算。
- **反算收购价**：给定目标回报率（IRR）或还本付息覆盖率（DSCR）的下限，系统能反解出**最高可接受的收购价**。
- 生成专用收购交付表和文件包（Word/Excel/CSV）。

### 2.7 零材料估算预览

没有任何甲方资料时，只凭一句话也能先出一版估算，用于内部初步判断。

**能做什么：**

- 说一句话（如"在湖北建一个年产 10 万吨磷酸铁锂项目"），系统自动识别行业、地区、大致规模、建设期，并列出还缺的关键参数清单（投资额、建设期等）。
- 按参数敏感度列出 5–10 个最需要确认的参数，人工逐项确认（或明确跳过）。
- 生成**估算预览包**：全套财务测算表 + 可导出 Excel/CSV + 技术说明文档。
- 预览阶段产出明确标注为"估算预览，不可正式上报"；只有完成独立质量审查、并由责任人显式确认晋升后，才转为可正式使用的材料。

### 2.8 规划测算

在财务测算之前，系统支持把"市场需求、建设规模、成本、人员"等关键输入先算清楚。

**能做什么：**

- 市场容量与需求测算、收入驱动因子测算。
- 建设规模方案：给定目标产能和用地，系统按约束（容积率、建筑密度、绿化率、绿地面积）确定性算出各方案是否可行。
- 投资成本核算：数量 × 单耗 × 单价 × 换算系数 × 损耗率，逐项可追溯。
- 定员方案：按工作量 ÷ 单人班次产能 × 班次 × 覆盖率 × 自动化因子 推导各岗位人数。
- 多方案对比评分、政策依据梳理。
- 这些规划结果都是不可变对象——一旦确认，后续所有测算都基于它；如果改，会明确提示哪些下游结果已经失效需要重算。

### 2.9 知识与经验沉淀

做得好的报告章节、审查经验、领域规则，可以沉淀成"知识候选"，经独立复核后发布，供后续项目复用。每个知识候选必须绑定证据和评分依据，不能凭印象收录。

## 3. 流程说明

### 3.1 总体流程一览

一份完整可研从立项到发布，一共走 **9 个阶段**，全程按固定顺序推进：

```
① 立项 → ② 收资料 → ③ 联网调研 → ④ 建证据 → ⑤ 做规划 → ⑥ 财务测算 → ⑦ 写报告 → ⑧ 审报告 → ⑨ 发布
```

流程的三条基本原则：

- **顺序不可乱**：必须"先有资料、后有测算、再有报告、最后审查"，不能跳步。
- **每步留痕**：阶段状态、修改记录、审查结论全部存档，可追溯。
- **改了要连锁重算**：任何上游内容变化，系统会自动标记所有依赖它的下游结果"已失效"，提示需要重新计算。

### 3.2 阶段明细表

| 阶段 | 做什么 | 谁来做 | 产出物 | 质量关口 |
|---|---|---|---|---|
| ① 立项 | 登记项目名称、行业、地区、性质、交易结构 | 业务人员 + 系统 | 项目登记记录 | 项目信息完整 |
| ② 收资料 | 导入甲方提供的 Excel/Word/PDF；检查 Excel 公式和跨表引用 | 业务人员 + 系统 | 入库资料 + 资料清单 | 文件安全、解析成功 |
| ③ 联网调研 | 公网搜索政策、市场、行业资料并固化快照；必要时做一轮深度研究 | 系统 + AI 助手 | 资料快照 + 研究报告 | 来源真实、引用可查 |
| ④ 建证据 | 把资料里的关键数字提取出来，多来源比对，固化成证据包 | 系统 | 证据包 | 数字有来源、口径一致 |
| ⑤ 做规划 | 市场容量、建设规模、成本、定员、方案比选 | 系统 + 业务人员确认 | 规划方案 | 规模口径合法、方案可比 |
| ⑥ 财务测算 | 建财务模型 → 出全套报表 → 勾稽校验 | 系统 | 财务模型 + 14 张表 | 勾稽一致、口径合法 |
| ⑦ 写报告 | AI 起草 → 人工逐章审定 → 数字一致性检查 → 导出 Word | AI 起草 + 人工审定 + 系统把关 | 报告初稿 / 正式候选 | 结构齐全、数字与测算一致 |
| ⑧ 审报告 | 七维度审查 → 出问题清单 → 整改 → 复测 | 系统检查 + 独立审查 + 人工整改 | 审查报告 + 整改记录 | 无未关闭的致命/严重问题 |
| ⑨ 发布 | 全部通过后正式发布 | 系统 + 责任人确认 | 发布成果（全程留痕） | 正式资格门禁 |

### 3.3 三种启动场景

#### 场景一：有甲方资料（走完整 9 阶段）

最完整的路径。从甲方提供的立项批复、可研初稿、财务底稿出发，一路做到正式发布。适合正式项目。

#### 场景二：零材料（一句话快速估算）

没有任何资料时，只靠一句话先出一版估算预览，供内部初步判断，**不能正式上报**。

```
一句话描述项目 → 系统识别行业/地区/规模 → 列出待确认参数 → 人工确认或跳过
→ 生成估算预览包（测算表 + 说明文档）
```

#### 场景三：资产收购（专项流程）

收购酒店或光伏电站走专项测算，不套用新建项目逻辑。

```
校验收购参数 → 确认 → 跑模型（酒店月度 / 光伏年度）→ 多情景组合 / 反算收购价
→ 生成收购报表与文件包
```

### 3.4 阶段状态与恢复机制

- **六种状态**：每个阶段的状态全程记录——待办、进行中、部分完成、受阻、已完成、已失效。
- **中途存档恢复**：任何阶段都可以保存检查点，之后从检查点继续，不需要从头再来。
- **变更连锁提示**：改了上游内容（比如换了投资额），系统会自动把下游所有结果标记为"已失效"，提示需要重算，避免用过期的数字。

### 3.5 流程中的角色分工

| 角色 | 在流程中负责什么 |
|---|---|
| **业务人员** | 描述项目需求、确认关键参数、逐章审定报告、做最终判断和签字 |
| **AI 助手** | 按既定流程调用系统能力，完成检索、测算、起草、审查；向业务人员汇报结果 |
| **系统（绿科）** | 用确定性算法计算、制表、校验、审查、留痕，把住质量关口 |
| **专业审查人** | 在系统检查之外做专业判断，负责合规性等专业结论的最终批准 |

一句话：**业务人员定方向，AI 助手干杂活，系统把质量关，专业审查人做终判。**

## 4. 质量与可信度机制

### 4.1 数字可信度分级

系统给每个数字标注"来源等级"，不同等级允许的用途不同：

| 来源等级 | 含义 | 允许用途 |
|---|---|---|
| 正式证据 | 来自甲方原始资料并经过验证 | 通过审查后可用于正式交付 |
| 来源重建 | 依据现有资料推算（原始依据不全） | 仅限内部验收 |
| 技术验证 | 仅用于验证计算逻辑对错 | 不得用于正式交付 |
| 受控假设 | 无资料时由人工确认的假设值 | 仅用于估算预览，不得正式交付 |

### 4.2 关键原则

- **算错了就停**：投资额与行业量级明显不符、关键假设缺失这类"口径错误"，系统**直接阻断**，不算出假数字继续往下走。
- **没把握就明说**：流程没走完、证据不足这类"置信度不足"情况，系统可以出中间件，但必须如实标注，不能伪装成最终结果。
- **一切留痕**：每个修改、每个审查结论、每次发布，都有不可变的记录，可以追溯。
- **"成功"不等于"合格"**：系统说"跑通了"只代表技术上完成，不等于该交付物可以对外正式使用；是否达到正式交付资格由独立的质量门禁判定。

## 6. 它不做什么（边界）

诚实说明系统的边界，避免误解：

- **没有面向终端的网站界面**。系统通过 AI 助手对话使用，不是给最终客户自助操作的 Web 应用。
- **不替代专业签审**。合规结论、专业判断、签字盖章仍是人工职责；系统只做确定性计算和检查，不替人签字、不假装完成了专业审查。
- **不验证资料本身的真伪**。系统处理的是你导入的资料，它验证"引用的内容与资料一致"，但不验证资料（如公章、批复、银行流水）本身是否真实——那是尽职调查的范围。
- **外部检索依赖第三方**。联网检索依赖外部搜索服务，对方不可用时系统会如实报告故障，不会用其他来源冒充。
- **Word 导出通过格式转换检查，未做逐页人工视觉验收**（如打印排版、页边距、分页）。
- **识别 Excel 的公式和结构，但不执行其中的宏。**
